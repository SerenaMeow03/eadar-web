## 谊达翻译管理后台 R1 改造完成

**项目位置**：`E:\DY\eadar`（静态 Netlify 部署：https://eadar-web.netlify.app）

### 改造背景
- 原系统前端直接调 Supabase，anon key 暴露 + RLS 全开 = 严重安全漏洞
- 管理员有两条登录入口：Netlify Identity（`/admin/index.html`）+ Supabase Auth（`/translator/admin/login.html`），用户容易混淆
- 译员 `translators` 表和 `auth.users` 没外键关联，UUID vs 文本 ID 错配
- 改密码逻辑走 `translators.password` 明文字段，但登录走 Supabase Auth —— 两套系统对不上

### 改造内容（R1 = 安全加固 + 统一登录）
- **新 schema v2**：`supabase-schema-v2.sql`，基于 auth.uid() + role + 所有权写 RLS
- **后端 7 个新 Netlify Functions**：get-orders、get-translators、get-translator-me、save-order、delete-order、update-translator-bank、update-password
- **改写 create-translator**：创建后写 `translators.auth_user_id` 关联
- **5 个前端 HTML 改造**：去掉直接 supabase 调用，统一走 fetch apiCall
- **修复密码 bug**：管理员和译员改密码都走 Supabase Auth updateUser
- **废弃 /admin/index.html**：加废弃提示和重定向
- **.gitignore** 加 .env；新增 .env.example 和 netlify-env-setup.md
